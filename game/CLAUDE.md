# Let's Eat! — Game code

Brief for Claude Code sessions building the Phaser game on the `game/prototype` branch (worktree `Lets-Eat-game`).
The Orchestrator role in the root `CLAUDE.md` does not apply here.

## Ground rules
- `docs/game_bible.md` is the source of truth for scoring, emotions, art names and tone. If the code and the bible disagree, the bible wins; if something isn't in the bible, ask Gabriella.
- `content/`, `scripts/`, `logs/`, `docs/` and `.claude/agents/` are **read-only** here. They belong to the content crew. If content looks wrong, report it; never patch it from the game side.
- The game reads content directly: `content/levels/*/`, `content/registry/*.json` and `scripts/rules.json` (the Validator's tag map and scoring thresholds). New levels arrive by merging `master` into `game/prototype`, with no copy step.
- No runtime AI calls, no network fetches: everything is bundled at build time.

## Layout
```
game/
  index.html, vite.config.js, package.json
  src/main.js                  Phaser config, exposes window.__game (used by tests)
  src/content.js               bundles the content files (import.meta.glob)
  src/logic/levels.js          raw files -> level models (pure, shared with tests)
  src/logic/scoring.js         bible scoring rules (pure, shared with tests)
  src/ui/                      theme, buttons, placeholder art, scroll areas
  src/scenes/                  Boot -> Menu -> Chat -> Results -> Outcome
  test/boot-test.mjs           Node: game scoring must agree with every outcomes file
  test/browser-boot.mjs        headless Chrome/Edge: every scene boots for every level
```

## Commands (from `game/`)
- `npm run dev`: dev server. Add `?all` to unlock every level. These URL shortcuts work only on the dev server; a built game ignores them, so locked levels stay hidden.
  Jump to a scene: `?scene=Chat|Results|Outcome&level=level_03[&venue=<id>][&highlight=craving][&revealAll][&recap]` (`&recap` opens the Outcome clue recap).
- `npm run build`: production build into `game/dist/`.
- `npm run boot-test`: both tests. Root `npm run boot-test` calls this; it is Integration's check 5
  (`LETS_EAT_LEVELS=level_01,level_02 ...` limits and orders the levels). Needs Chrome or Edge installed.

Run `npm run boot-test` before every commit.

## Decisions taken in the prototype (confirm with Gabriella)
- **Scoring is computed by the game** from the spec and registry, and only the reaction lines come from `outcomes_*.json`. The boot test fails if the two ever disagree.
- **Notebook shows the quote, not the clue tag.** Showing "Diet: vegetarian" would solve implied clues for the player.
- **Venue cards show name, cuisine and price only.** Dietary and vibe tags are left for the reviews to reveal.
- **Venue order is shuffled**, with a fixed seed per level, because venue files often list the answer first.
- **Unlocks:** a level opens once the previous one is cleared (1+ stars); locked levels are hidden, not shown greyed out (Gabriella, 2026-11-06). Best stars are kept in localStorage.
- **Notebook is on the chat and the restaurant list**, same place on both (`src/ui/notebook.js`) (Gabriella, 2026-11-06).
- **Outcome image slot** on the result screen. First texture found wins: `outcome_<level>_<venue>`, then `outcome_<level>_<perfect|partial|fail>`, then `outcome_<result>`. Until one exists, a placeholder names the file it expects.
- **Palette and fonts** come from Gabriella's portrait sheets (`src/ui/theme.js`): Pixelify Sans (bundled, no network) for headings and buttons, a plain sans for chat and reviews.
- **Fail hint** names the broken hard constraint; "Reread the chat" highlights the tagged lines for every miss.
- **Chat pacing** (`TYPING_MS` in `ChatScene.js`): messages arrive on their own after a "<name> is typing" bubble that lasts 1 s (Gabriella, 2026-11-11). Controls: a tap on the chat panel (not the Notebook, not a drag), space or enter shows the next message; A shows the whole chat; P pauses/resumes. The chat also waits while the player is scrolled up (wheel, drag, arrows, Page Up/Down, Home/End) or rests the pointer on an older message for 0.3 s; any player scroll clears the hover pause. Reread-after-a-miss and `?revealAll` stay instant. The typing row uses the NEUTRAL portrait so it doesn't give away the next line's mood, and sits at 0.8 alpha (dimmer while paused) so it never reads as an empty message. Critic review of the pacing (2026-11-11): pass.
- **Notebook pins from chapter 2** (`PIN_FROM_CHAPTER` in `src/ui/notebook.js`) (Gabriella, 2026-11-11). Chapter 1 still auto-quotes tagged lines, as a tutorial for what a clue looks like. From chapter 2 (where implied clues start) the Notebook only keeps lines the player pins with the star beside each message (a push-pin until Gabriella switched it to a star, 2026-11-11). A starred message gets an orange star and a soft cream bubble with a thin orange edge (`C.starred`); the yellow "missed line" highlight wins if both apply. Any line can be pinned, so pinning never reveals which lines are clues. A framed callout at the top of the Notebook and its empty state tell the player to pin; the key hint line says it too (player-facing text says "star"; code still says "pins"). Pins are kept per level in the game registry (`pins:<level_id>`), carry over to the restaurant list and back, and reset when the level is opened fresh (menu or "next level"). The restaurant list shows only pinned lines in pin levels. The critic raised it because auto-quoting copies exactly the tagged lines and so gives away implied clues.
- **Clue recap** on the Outcome screen (`src/logic/recap.js`, "Clue recap" button) (Gabriella, 2026-11-12). A panel lists each scored need with ✓/✗ for this pick, its kind (must-have = allergy/diet, limit = budget, nice-to-have = craving/vibe/intolerance) and every chat line tagged with it; missed needs come first. In star levels each line also says whether the player starred it. After a fail it shows only the broken need (already named by the hint), so a retry isn't handed the whole answer. Closes with Close, Esc or a click outside. The Node boot test checks every recap row has a chat line and agrees with scoring.
- **Scrapbook** (bible: Callbacks, Scrapbook; `src/scenes/ScrapbookScene.js`, `src/logic/scrapbook.js`, `src/ui/scrapbookStore.js`) (2026-11-12). Pages come from `scripts/rules.json` `callbacks` (mirrors the bible table: title, page, `page_from_chapter`, art). Reading a dialogue line with `"callback": "<id>"` unlocks that page for good (localStorage `lets-eat-scrapbook-v1`). Menu: "Scrapbook n/5" button. Outcome: a "new scrapbook page" note once per visit when the level unlocked one. Locked pages show only "???". Art: `scrap_<id>` loaded from the art manifest's `scrapbook` group; until it exists a placeholder names the file. "Reached a chapter" (for `page_from_chapter`) = played at least one of its levels. Pages only unlock once the tagged dialogue (retrofit/callbacks) has reached master and been merged in here.
  - **Unlock card** (Gabriella, 2026-11-12): ~1.4 s into the Outcome screen, a "NEW SCRAPBOOK PAGE!" card slides up, the page's badge pops in with rays and sparkles, then title and friend. "See it" opens that page in the Scrapbook; "Keep going" closes it ("Next page →" when a level unlocked two). Esc also closes. Shown on the Outcome screen, never in the chat, so it can't flag which line was a callback. The small corner note stays too. Not yet in the bible (its Scrapbook "Where" row only mentions the small note).
  - **Badges** (`src/ui/badge.js`): each page has a badge, shown on its Scrapbook row, as a sticker on the page and on the unlock card. Real art replaces it key for key as `badge_<id>`; until then a placeholder rosette in the friend's colour with the title's initials. Locked pages get a grey "?" rosette (no colour or initials, so no hint). Badge art is not in the bible yet. The page also says which level it was found in.
- **Been here before** (`src/logic/beenHere.js`, `src/ui/visitStore.js`, Results screen) (2026-11-12). Opening a level's search results records its venues as seen; recommending one records it as picked (localStorage `lets-eat-venues-v1`). A recurring venue the player met in an EARLIER level (by level number, so replays never show later reviews) gets a pill on its card: "BEEN HERE" (orange) if they picked it before, "SEEN BEFORE" (blue) if it was only listed. Its detail panel adds a "FROM LEVEL N" section (the most recent earlier level) with that level's reviews and "you sent the crew here in level N" when picked. It never shows how an earlier pick scored: Koi Counter is a decoy in level_06 and the answer in level_08. Reviews now scroll, with a "↓ scroll for more" hint. The Node boot test checks every recurring venue (no badge on first appearance, points back to the right level and reviews, no score fields). Not in the bible.
- **Sort and filter on the restaurant list** (`src/logic/resultsView.js`, top of the Results list) (2026-11-12). SORT: Mixed (the level's seeded shuffle, still the default so the answer isn't on top), Cheapest, A–Z; sorts are stable. SHOW: toggle chips for each price tier and, when the level has more than one, each cuisine; several at once, none = all; the row is left out when there's nothing to choose. Uses only what the cards show, so no hidden dietary or vibe tag can leak. The choice is kept in the registry (`resultsView:<level_id>`) and survives a trip back to the chat. A selected place hidden by a filter is deselected; no matches shows "Clear filters"; a filtered list says "N of M places". Card size comes from the full list, so cards don't jump; short cards (6–7 venues) use smaller text. The Node boot test checks sort order and filters for every level. Not in the bible.
- **Accessibility options** (`src/scenes/OptionsScene.js`, `src/ui/settings.js`, `src/ui/motion.js`; menu "Options" button or O) (2026-11-12). Saved per browser (localStorage `lets-eat-settings-v1`), applied at once.
  - **Text size** Normal / Large (×1.2) for text people read: chat, reviews, Notebook, reactions, recap quotes, scrapbook pages. Use `readText()` from `theme.js` for any new reading text; buttons and labels stay `text()`/`pixel()` so layouts hold.
  - **Chat pace** Quick 1 s (default, Gabriella 2026-11-11) / Relaxed 2 s. A "Tap to continue" choice was removed (Gabriella, 2026-11-12); a saved one falls back to Quick.
  - **High contrast** reapplies `C` in place (`applyPalette()`): black ink, off-white panels (white bubbles still show on them), stronger accent/highlight, chat backdrop at 25%. Never copy a `C` colour into a module-level constant; read it when drawing (see `BADGE` getters in ResultsListScene). Text on the dark page background uses `C.label`, not `C.inkSoft`.
  - **Reduce motion** (on by default when the OS asks for reduced motion): every animation goes through `tween()` in `src/ui/motion.js`, which jumps to the end values instead. Use it instead of `this.tweens.add` for anything new.
  - For everyone: empty stars have an outline, and the result screen says "N of 3 stars".
  - Options screen works by keyboard (↑ ↓ setting, ← → choice, Esc back) with a focus ring and a live preview. Not in the bible.
- **Credits file** (`public/credits.json`; bible: Game identity > Audio). `{ "_about", "music": [], "art": [...] }`. Each music track: file, title, artist, source (Bensound | Pixabay Music), license, credit_line, url. Gabriella adds tracks by hand; agents never pick or download music, so `music` starts empty. `art` has one entry crediting the portraits and venue art as Gabriella's own (Nano Banana pixel art). `BootScene` loads it and stores it in the registry as `credits` (empty lists if missing), ready for the credits screen, which isn't built yet (feature agent, 2026-11-12).
- **Music credits filled** (`public/credits.json` `music`). One entry per audio file in `public/music/` (14 Pixabay tracks Gabriella downloaded), sorted by file name, each with file, title, artist, source "Pixabay Music", license "Pixabay Content License", url, license_file and credit_line "<title> by <artist> (Pixabay)". A track is matched to its `*-license.txt` certificate by the Pixabay ID in both file names; with one (5 lafrey_music tracks), title, artist (Licensor's username) and url come from the certificate and license_file points to it. Without one (9 tracks), title and artist are guessed from the file name (`<username>-<title words>-<id>`), url and license_file are null and `"check": true` asks Gabriella to confirm the names (doubtful: the numeric usernames 23843807 and 51383504, and whether "alex-morgan" is the username). Music files are never chosen, renamed or deleted by agents. BootScene still loads it into the registry as `credits` (feature agent, 2026-11-13).
- **Credits screen** (`src/scenes/CreditsScene.js`, scene key `Credits`; bible: Game identity > Audio). Reached from the menu's "Credits" button under Options (or C); back with "← Levels" or Esc. Lists every entry of the registry's `credits`: MUSIC (title, then artist, source, license and the credit line) and ART (what, artist, source, license, credit line). With no music it says so plainly. The list scrolls (`ui/scroll.js`: wheel, drag, ↑ ↓, Page Up/Down, Home/End) with a "↓ scroll for more" hint; entry text uses `readText()`, so Large text applies. No animation. The browser boot test opens it (`?scene=Credits`) (feature agent, 2026-11-13).
- **Background music** (`src/ui/music.js`; bible: Game identity > Audio). Plays only the tracks in the registry's `credits.music`, loaded by `BootScene` from each entry's `file` under the key `music:<file>` (`musicKey()`). Tracks play in list order at volume 0.25 and loop back to the first. Nothing plays until the player's first click or key press, because browsers block autoplay. If the list is empty or a file fails to load, music does nothing and never throws. Exports `start(scene)` (BootScene calls it once credits are in the registry), `setEnabled(on)` and `isEnabled()`. The on/off choice is saved in localStorage as `lets-eat-music-v1`, but no menu or Options control uses it yet (feature agent, 2026-11-13).
- **Music option** (`src/ui/settings.js` `music`, Options screen "Music" row; bible: Game identity > Audio). On / Off, default On, saved with the other settings. Choosing it calls `setEnabled()` in `src/ui/music.js` at once (Off stops the current track; On resumes after the first click or key press). At boot, `BootScene` applies the setting to `music.js` if its own saved on/off disagrees, so the Options choice wins. The Options rows are a little shorter (98 px) so five fit above the key hint (feature agent, 2026-11-13).
- **Star totals** (`src/logic/progress.js` `starTotals(levels, progress)`, Menu; bible: Scoring rules, Campaign structure). Counts only built levels, 3 stars each, using each level's best stars (clamped to 0–3; progress for unbuilt levels is ignored). Returns `{ byChapter: { <chapter>: { earned, max, perfect } }, earned, max }`. The menu shows "★ earned / max" at the right of each visible chapter heading, with a "PERFECT" mark in `C.highlight` when every built level in that chapter has 3 stars, and the campaign total top right under the Scrapbook button. The Node boot test checks empty, full and partial progress (feature agent, 2026-11-13).
- **Chapter intro cards** (`src/ui/chapterIntro.js` `showChapterIntro(scene, chapter, onDone)`; bible: Campaign structure > Calendar). A card over the screen with "CHAPTER N", the district, the season and the Calendar's "typical reasons" line, word for word (no new story text; the bible's tag notes like "so `quick_bite`" are left out so the card doesn't hint at clues). Chat shows it before the first message the first time any level of that chapter opens, never automatically again (localStorage `lets-eat-chapter-intros-v1`, in-memory fallback if blocked); `revealAll` (reread after a miss) skips it. Tapping a chapter heading on the menu shows it again. Closes with a click on the card (only a press that began on it), Enter or Esc; while it's up the chat's space/A/P/clicks do nothing. Fades and slides in through `tween()`, so Reduce motion shows it at once. Not in the bible as a screen (feature agent, 2026-11-13).
- **How to play** (`src/ui/howToPlay.js` `showHowToPlay(scene, onDone)`; bible: Game identity > Core loop). A three-step overlay, each step framing (pulsing outline, label, arrow) the part of the chat screen it means: 1. read the group chat and notice what each friend needs (the chat panel); 2. tap "Find a place", open each place and read its reviews (that button); 3. recommend the one place that suits everyone (the Notebook). Next / Skip buttons on every step, Enter next, Esc skip. Chat shows it before the first message the first time level 1 opens, before the chapter card (localStorage `lets-eat-how-to-play-v1`, try/catch, in-memory fallback); `revealAll` skips it. Options has a "How to play" button under the preview (or H) to see it again; the Options keys wait while it's up. Animated only through `tween()`. Not in the bible as a screen (feature agent, 2026-11-13).

## Art
- Source sheets: `art/source/<character>_sheet.jpg`, a 3x2 grid of HAPPY ANNOYED SURPRISED / ANGRY CONTENT NEUTRAL.
- Outcome pictures: `art/source/level_XX_result_<venue name>.jpg` (3:2, venue name without the district, e.g. `level_01_result_satay_spot.jpg`). The script below cuts them to 680x456 as `outcome_level_XX_<venue id>`.
- Chat backdrops: `art/source/chat_background_chapter_XX_<district>.jpg`, tall pictures work best. The script keeps the whole picture, only muting it (`MUTE_SATURATION`, `CREAM_WASH`), and saves `chat_bg_chapter_XX`. ChatScene shows it at the panel's width for every level in that chapter and pans down it: by reading progress while messages arrive, then with the scroll position once the chat is fully shown.
- **Preview portraits** are cut by `python game/tools/slice_portraits.py` into `game/public/art-preview/` (PNGs + manifest). `BootScene` loads that manifest; anything it doesn't cover (cuisine icons for now) gets a generated placeholder under the bible's key.
- The official assets are the Art Asset agent's job (`public/assets/`). When they exist, change `MANIFEST` in `BootScene.js` and serve the root `public/` folder.
